# vinext-starter

A clean full-stack starter running on
[vinext](https://github.com/cloudflare/vinext), with optional Cloudflare D1 and
Drizzle support.

## Prerequisites

- Node.js `>=22.13.0`

## Quick Start

```bash
npm install
npm run dev
npm run build
```

This starter does not use `wrangler.jsonc`.

## Included Shape

- edit site code under `app/`
- `.openai/hosting.json` declares optional Sites D1 and R2 bindings
- `vite.config.ts` simulates declared bindings for local development
- `db/schema.ts` starts intentionally empty
- `examples/d1/` contains an optional D1 example surface
- `drizzle.config.ts` supports local migration generation when needed

## Authentication

The CMS and write APIs are protected by a JWT session cookie (`dpp_session`, `HttpOnly`, `SameSite=Lax`). `POST /api/auth/login` issues the token; both the Next route handlers and the Express API verify it locally with `AUTH_SECRET`, so no shared session store is needed.

- Public: `/`, `/login`, `/dpp/:milRef`, `GET /api/dpp/traceability/:milRef`, `GET /api/health`.
- Requires login: `/cms/*`, `/api/dpp/pages`, `/api/dpp/node-mappings`, `GET /api/dpp/supply-chain/:milRef`.
- The first admin is created on first login while the users table is empty, using `AUTH_BOOTSTRAP_EMAIL` and `AUTH_BOOTSTRAP_PASSWORD`. Remove those two variables after the first login.
- `reviewedBy` for node mappings comes from the session, never from the request body.
- Run `npm run db:migrate` after adding migrations. Set `AUTH_COOKIE_SECURE=true` once the site is served over HTTPS.

## Deployment (Windows / on-prem)

- `npm run build`, then `vinext start` serves the app on `127.0.0.1:3000`; the Express ERP API (`server/index.ts`) listens on `4000`. Apache proxies both.
- In Node production the database is SQLite at `data/dpp.sqlite` (override with `DPP_SQLITE_PATH`). The `vinext dev` server keeps using the local Cloudflare D1 binding in `.wrangler`, so dev and production data are separate by design.
- `scripts/install-services.ps1` (run as Administrator) applies migrations, registers the Scheduled Tasks `DPP App (vinext 3000)` and `DPP API (express 4000)` with boot trigger and restart-on-failure, then starts them. `scripts/uninstall-services.ps1` removes them. Logs go to `logs/`.
- `scripts/service-env.cmd` is generated by the installer and stores the absolute Node path.

## Useful Commands

- `npm run dev`: start local development (D1 binding)
- `npm run build`: verify the vinext build output
- `npm start`: start the production server (SQLite)
- `npm run db:generate`: generate Drizzle migrations after schema changes
- `npm run db:migrate`: apply migrations to the production SQLite database
- `npm test`: build the starter and verify its rendered loading skeleton
