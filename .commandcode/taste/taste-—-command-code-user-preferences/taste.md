# Taste — Command Code user preferences
- Writes in Indonesian and expects replies/explanations in Indonesian. Confidence: 0.75
- Reports bugs with the raw failing evidence and almost no prose — verbatim framework error output/stack traces, or a screenshot of the broken screen plus a one-line "sudah bisa, tapi…" — and expects the assistant to diagnose the root cause from it and fix it. Confidence: 0.65
- Expects data values (locations, coordinates, addresses, etc.) to be derived from the project's own source documents (e.g. COC spreadsheets, manifests) rather than city-level or placeholder approximations. Confidence: 0.7
- When correcting data, expects the work grounded in a verifiable source and the discrepancies explained. Confidence: 0.6
- Double-checks data values he didn't verify himself and expects the assistant to re-verify each one against a source when challenged, rather than restating the earlier answer. Confidence: 0.75
- Expects data that is assumed, approximate, or missing in the source to be marked as unverified rather than presented as documented fact. Confidence: 0.55
- Audits UI/feature behavior against the underlying data record count and objects to lossy simplifications — a stage with 4 trader locations and 2 spinner locations reduced to one representative point, or multiple actors in a process merged into a single chained route/polyline; expects every distinct data point to be represented individually in the interaction (e.g. one route segment per actor). Confidence: 0.7
- Deploys to the company's own on-premise server (Windows + XAMPP/Laravel already running there) and prioritizes not destabilizing existing services — wants deployment options that add no extra supervised process and can't take down already-critical apps on reboot/restart (separate vhost/port or a subfolder under the existing XAMPP htdocs, static files served by Apache, no new runtime introduced next to the running Laravel app). Confidence: 0.65
- Describes his server environment by walking the actual filesystem layout (e.g. "D - xampp - apache - conf - extra - httpd-vhost.conf", "htdocs") and expects concrete instructions targeting those exact paths/files, not generic deployment guidance. Confidence: 0.55
- States an operational concern up front and expects the assistant to first clarify feasibility/architecture constraints (what the stack can and cannot run) before proposing step-by-step deployment instructions. Confidence: 0.5
- Asks short clarifying questions in Indonesian when a behavior looks intentional-vs-buggy ("tombol edit nya masih belum bisa bekerja ya?") and expects a direct yes/no answer, the cause explained, and — for a stub/unimplemented control — a walkthrough of what actions it will perform before anything is coded. Confidence: 0.6
- Prefers a decluttered UI: asks to strip non-essential display extras — coverage/verification chips like "81% documented", per-item status badges (Complete/Partial/Declared/Not documented) on step and process cards, and whole sections of a tab (product spec lists, care cards, the "badge evidence" cards with their supported/partial/pending counters) so a screen shows only its stated essentials, e.g. just the photo and the material composition, or just the certification logo grid on the badges tab. Confidence: 0.65
- Asks for analysis/architecture review first ("coba anda lakukan analisis terlebih dahulu") and expects no code written until current state, data model, tradeoffs, risks, and open decisions have been laid out and he has picked a direction. Confidence: 0.6
- Prefers data-driven/templated designs over hardcoded single-instance content — e.g. a CMS whose pages are generated per product category rather than one hand-built page per product. Confidence: 0.5
- Expects edit/settings forms to size themselves automatically from the source record count instead of assuming a fixed number of rows — e.g. page settings must render one composition-note field per fibre the ERP returns, working the same whether the lot has 1 or several fibres (50% cotton + 50% other fibre). Confidence: 0.6
- Leaves backend/database choices deliberately open ("belum tau akan integrasi dengan db dan backend nya saya belum tau akan menggunakan apa") and works locally first — expects the architecture to keep those decisions deferrable (swappable data-access/repository layer, avoid opinionated framework lock-in) rather than have a stack imposed early. Confidence: 0.5
- Comes from a PHP/Laravel background (Filament is his mental model for admin/CMS tooling) and is not familiar with the TypeScript/React library and package ecosystem — expects library/package recommendations to be explained by mapping them to the Laravel/PHP equivalents he already knows, rather than assumed TS fluency. Confidence: 0.6
- Wants commits pushed to his own GitHub account, not whatever `origin` happens to be configured to — expects the target remote/repo to be confirmed rather than assumed from the repo's existing config. Confidence: 0.55
- Extends the read-only principle to the UI: data already loaded from the legacy ERP/reference tables (supplier, country, lot, quantity, documents) must stay read-only in edit forms — the edit surface may only add mapping/metadata on top (e.g. stage, process label, notes, review status), never rewrite the fetched values. Confidence: 0.6
- Expects generated/dynamic pages to reuse the existing app's design and components (e.g. "page yang akan di generate itu akan seperti /") rather than ship a new, simpler custom layout — visual and structural consistency with the already-built page is the requirement. Confidence: 0.55
- Expects app-side taxonomies/enums to enumerate every distinct value that actually exists in the source ERP data: he flags a hardcoded stage list narrower than the ERP's real role values (6 stages vs 10 roles, e.g. Dyeing/Finishing folded into weaver, Customer and "Other" missing entirely) as a bug, including that catch-all values like "Other" must still surface the specific sub-label stored in ERP; the same goes for fibre/composition types, which must cover the ERP's real set (cotton, polyester, elastane, viscose, wool, other) instead of a hardcoded subset. Confidence: 0.65
- Wants image/icon assets in the project restricted to genuine PNG files — when pointing at an asset folder for UI icons ("pastikan hanya gunakan file dengan format .png"), files that merely carry a `.png` extension but are actually JPEG/WebP must be excluded rather than used. Confidence: 0.6
- Insists that database access to the production/legacy ERP be strictly read-only: SELECT/CTE queries only, no stored-procedure execution, and a code-level guardrail that rejects manipulation keywords (INSERT/UPDATE/DELETE/DROP/TRUNCATE/ALTER/EXEC) before any query reaches SQL Server — safety enforced in the module, not just by convention. Confidence: 0.7
